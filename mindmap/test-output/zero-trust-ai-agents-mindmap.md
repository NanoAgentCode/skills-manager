# Zero Trust for AI Agents

## 核心观点
- 边界防御跟不上 AI 加速攻击
- 智能体引入自主执行风险
- 安全架构要从第一天假设已被攻破
- 控制目标是让攻击不可行，而不是更麻烦

## Zero Trust 原则
- 永不默认信任
  - 所有访问都要认证和授权
  - 内外部请求同等审查
- 假设已被攻破
  - 通过隔离和分段限制损害
  - 单点失陷不能扩散到全局
- 最小权限
  - 只授予完成任务所需权限
  - 控制单个身份的爆炸半径
- 设计测试
  - 优先硬边界
  - 少依赖摩擦、限速和隐藏端口
  - 偏好硬件凭证、短期令牌、加密身份

## 智能体特殊风险
- 自主多步操作
  - 无需每一步人工批准
  - 被操纵后可机器速度执行危害
- 工具访问
  - 可连接 API、数据库、文件系统和 MCP
  - 合法权限也可能被错误使用
- 决策歧义
  - 指令解释存在可攻击空间
  - 良性目标可能产生危险路径
- 上下文持久化
  - 记忆提高能力
  - 也带来污染和泄密风险
- 多智能体协作
  - 一个智能体可成为横向移动入口
  - 隐式信任关系需要验证

## 当前威胁
- Prompt 注入
  - 直接覆盖系统指令
  - 间接隐藏在网页、邮件和外部资料中
  - 模型难以稳定区分上下文和命令
- 工具和资源滥用
  - 工具描述、schema、metadata 被投毒
  - 合法工具被链式组合外泄数据
  - 循环调用造成成本或拒绝服务
- 身份和权限滥用
  - 高权限智能体错误委派
  - 低权限智能体诱导高权限智能体执行
  - 缓存凭证跨会话扩大权限
- 供应链风险
  - 模型权重和微调数据后门
  - MCP、API 集成、框架依赖被污染
  - 开源依赖重复和维护不足扩大攻击面
- 记忆和上下文投毒
  - 恶意记忆影响后续会话
  - RAG 数据源被污染
  - 多租户共享上下文产生漂移

## 三层能力框架
- Foundation
  - 适合小团队和基础部署
  - 已要求加密身份、短期令牌和自动初筛
  - 不是静态 API key 或共享账号
- Enterprise
  - 大多数组织的目标成熟度
  - 增加证书身份、ABAC、不可变审计和自动化基线
  - 支持多部署和真实业务复杂度
- Advanced
  - 适合高监管和高价值目标
  - 使用硬件绑定身份、持续授权和实时响应
  - 代表未来可能下沉的标准能力

## 关键控制域
- 身份和认证
  - 每个智能体有唯一加密身份
  - 使用短期、窄范围令牌
  - 高成熟度采用 mTLS 和硬件绑定凭证
- 授权和权限
  - Foundation 使用静态最小权限角色
  - Enterprise 使用动态权限和属性访问控制
  - Advanced 使用 JIT/JEA 和持续授权
- 隔离
  - 基于身份隔离服务访问
  - 沙箱执行不可信工具
  - 高风险环境使用硬件隔离
- 可观测性
  - 记录工具调用、数据访问和外部通信
  - 关联请求 ID、分布式追踪和完整来源链
  - 日志进入不可变或实时流式系统
- 异常检测和响应
  - 建立正常行为基线
  - 检测工具使用、数据访问和输出特征漂移
  - 自动 containment 后再升级人工处置
- 输入输出防护
  - 输入验证、内容过滤、多层校验
  - 输出过滤和语义分析
  - 高风险操作引入人工审批
- 配置和治理
  - 版本控制配置
  - 签名配置和回滚流程
  - 持续策略验证和自愈能力

## 实施工作流
- 阶段 1：确定用例和风险
  - 定义智能体目标、工具和数据范围
  - 评估监管和业务影响
- 阶段 2：建立 AI-BOM
  - 记录模型、工具、依赖和数据源
  - 审查 OpenSSF Scorecard 和供应商安全实践
  - 合并重复依赖以减少攻击面
- 阶段 3：分配身份
  - 为每个智能体创建独立身份
  - 避免共享服务账号
  - 将日志与身份强绑定
- 阶段 4：防御 Prompt 注入
  - 分离指令和外部内容
  - 扫描提示词和响应
  - 限制外部内容可触达工具
- 阶段 5：保护工具访问
  - 工具 allow-list
  - 工具认证和范围控制
  - 参数验证、沙箱、速率限制和熔断
- 阶段 6：保护凭证和授权
  - 使用身份提供方签发短期凭证
  - 生产系统绑定硬件或托管身份
  - 委派任务时验证原始用户意图
- 阶段 7：保护记忆
  - 隔离用户和会话记忆
  - 标记来源并验证完整性
  - 对高风险上下文隔离、过期或回滚

## 防御运营
- 自动化第一轮分诊
  - 用只读工具辅助分析告警
  - 优先缩短 dwell time
  - 提高被调查告警覆盖率
- 身份驱动响应
  - 撤销短期凭证
  - 隔离异常智能体
  - 限制工具和网络路径
- 覆盖率管理
  - 映射 MITRE ATT&CK 检测覆盖
  - 重点关注横向移动和凭证访问
  - 用覆盖图指导改进路线

## 落地建议
- 从 Foundation 起步
- 用 Enterprise 作为多数组织目标
- 高风险场景直接采用 Advanced 基线
- 定期用“不可行 vs 只是麻烦”审查控制
- 把身份、权限、隔离、审计和恢复作为整体设计
