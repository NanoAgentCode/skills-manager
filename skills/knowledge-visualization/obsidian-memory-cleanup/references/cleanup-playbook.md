# Obsidian 长期记忆清洗手册

仅在执行全库或指定范围的语义清洗时读取本手册。自动审计只能发现结构风险，不能决定两条记忆是否语义重复或哪条事实更新。

## 一、建立可核查清单

对每条正式记忆记录：路径、标题、分类、`scope`、`status`、`source`、更新时间、主题、权威来源和可能重叠项。先统计总数，完成后逐条销账，避免把“抽查”误报成“全量审核”。

| 目录 | 权威内容 | 不应长期维护的内容 |
|---|---|---|
| `10-Projects/` | 项目目标、范围、角色、长期背景、知识入口 | 具体类名、端口、实现链路、模块数量 |
| `20-Knowledge/` | 技术机制、实现链路、验证方案、可复用知识 | 纯项目简介、稳定用户偏好 |
| `30-Decisions/` | 重要选择、理由、替代方案、影响 | 没有取舍依据的普通事实 |
| `40-Preferences/` | 用户明确或反复确认的稳定偏好 | 单次任务要求、项目实现细节 |

## 二、确定主题权威记忆

把候选重复分成四类：

1. **完全重复**：保留来源更清楚、结构更完整的一条，迁移仍有价值的链接后删除另一条。
2. **碎片互补**：合并到主题权威记忆，避免多个短笔记分别维护同一事实链路。
3. **总览与专项重叠**：总览只保留导航和跨链路公共证据；实现细节只在专项维护。
4. **历史与当前冲突**：保留历史记录，标记 `superseded` 并链接当前权威记忆，不把两种状态揉成模糊结论。

重复标题、相同正文、高相似度只是线索。相同的关联链接、生命周期记录和适用边界可能是合理重复，不应机械删除。

## 三、核查易漂移事实

优先核查版本、数量、路径、类名、接口、配置键、数据库名、品牌命名、测试覆盖、分支提交、远端发布状态，以及“自动迁移”“默认允许”“已经推送”等强结论。

证据优先级：

1. 当前用户指令。
2. 当前项目源码、配置、测试与 Git 状态。
3. 官方文档或可复现运行结果。
4. 有来源的历史记忆。

核验时记录仓库、分支或提交、证据文件和验证日期。不要修改被核查的源项目。找不到当前项目或无法运行验证时，写清证据缺口并使用 `uncertain` 或 `stale`，不要用旧记忆补足现状。

## 四、应用最小而完整的修改

- 先确定目标权威文件，再移动事实和更新链接。
- 改名时同步更新正式记忆、历史清单和关联链接。
- 保留 `created`，把实际复核日期写入 `updated` 和变更记录。
- `source` 应反映依据：`user-confirmed`、`project-file`、`verified-result`；推断使用 `inferred`。
- 不为形式统一重写无关段落，不触碰 `.obsidian/`。
- 不保存密码、API Key、令牌、Cookie、私钥或未脱敏个人信息。

## 五、完成证据矩阵

| 要求 | 完成证据 |
|---|---|
| 全量覆盖 | 清洗前后正式记忆总数及逐条清单 |
| 内容去重 | 重复候选及其保留、合并、删除或保留理由 |
| 碎片合并 | 权威记忆路径和被吸收来源 |
| 事实核验 | 当前源码、配置、测试、Git 或官方来源 |
| 分类调整 | 旧路径、新路径及分类依据 |
| 冲突处理 | `status: superseded` 与有效 `superseded_by` |
| 链接完整 | 断链、歧义链接和冲突标记均为零 |
| 检索有效 | 当前关键词命中 active 记忆；旧关键词仅命中纠错或历史语境 |
| 索引更新 | 本地索引已重建且包含新路径和状态 |
| 安全边界 | 敏感扫描无真实凭据，`.obsidian/` 未修改 |

## 六、交付说明

结果先说明实际发生的内容变化，再说明审计过程。至少包含审核与修改数量、关键过期事实及证据、重复处理理由、验证结论、索引状态和 Git 状态。尚未验证或需要用户决策的内容，不得隐藏在“清洗完成”结论中。
